# 变更契约与按需代码图谱

代码质量检查分为轻量开发准备、提交/推送检查和 CI。GitNexus 是按需的影响分析工具，应用运行、日常开发和自动质量检查均不依赖它下载或建立索引。权威上下文仍以仓库内文档为准。

## 个人 fork 的默认目标

本次及后续个人升级只提交、推送到 `Kai4nIS4n/code-tape`，PR 在该 fork 的分支与 `main` 之间创建，不默认向上游提交。

已有 `origin` 必须指向这个仓库；Git 可设置 `remote.pushDefault=origin`，GitHub CLI 可运行 `gh repo set-default Kai4nIS4n/code-tape`。这些属于本机仓库配置，新 checkout 需要核对，不会随 Git 提交传播。创建 PR 时仍应显式指定 `--repo Kai4nIS4n/code-tape`。

原培训用的认领、计分、自动合并、超时关闭及专用 Repo Guard job 只在 `ceilf6/code-tape` 运行。个人 fork 保留 `Workflow Tests / quality` 和 `Contract Guard / gitnexus-contract`。后者沿用已有检查名称以兼容自动合并和分支保护，但只运行轻量变更契约，不启动 GitNexus。

## 开发前准备

首次使用新 checkout 时，`npm install` / `npm ci` 或以下命令安装 hooks：

```bash
npm run agent:bootstrap
```

每次任务开始时运行：

```bash
npm run quality:predev
```

该命令只检查 hooks。若 `core.hooksPath` 已为 `.githooks`，读取后直接成功，不重复写 `.git/config`。首次没有配置时才写入当前仓库；CI 不安装本地 hooks。已安装的 checkout 无需反复 bootstrap，也不在开发前运行全部测试或图谱扫描。

## 提交与推送

- `git commit` 的 `pre-commit` 执行 `quality:precommit`：仓库测试、Schema/API/Web 测试、Web lint 和构建。
- `git push` 的 `pre-push` 保留 Git LFS 上传，并执行 `quality:local`：`contract:check` 加 `quality:ci`，后者包含 E2E。
- CI 的功能检查继续执行 `quality:ci`，不因 GitNexus 改为可选而删减。

通常由 hooks 负责对应命令，不必在每次提交/推送前手动重复跑同一质量门。诊断失败、hooks 未安装或明确绕过 hooks 时，手动执行对应检查并记录结果。

`SKIP_QUALITY_HOOKS=1` 仅跳过本地提交/推送的质量检查，不跳过 Git LFS 上传、不改变 CI。它是临时诊断手段，不是默认开发方式。

## 轻量变更契约

```bash
npm run contract:check
```

该命令读取当前 diff，不调用 `npx` 或联网刷新图谱。关键骨架变更仍要求匹配的契约测试及结构化影响摘要，主要覆盖录制 Schema、运行时、存储、回放核心、工作流和权威文档。

PR 摘要使用：

```md
## 影响分析摘要

- 风险等级: LOW|MEDIUM|HIGH|CRITICAL
- 关键骨架变更: 具体目录或符号
- 影响分析: 受影响的调用者、兼容性及风险，可写人工检查结论
- 验证结果: 实际执行的命令和结果，或未完成的原因
```

只检查摘要是否完整、风险等级和配套测试，不强制出现某个工具名称。旧的 `GitNexus 影响分析摘要` 标题、`GitNexus 影响面` 字段和 `GITNEXUS_IMPACT_SUMMARY` 环境变量仍兼容；新调用使用 `CONTRACT_IMPACT_SUMMARY`。

本地关键改动需要通过检查时，可通过 `CONTRACT_IMPACT_SUMMARY` 提供同一份摘要；PR CI 从正文读取。没有触碰关键骨架的普通改动无需凑一份工具报告。

## 按需运行 GitNexus

复杂的回放、Schema、运行时或存储改动可先使用图谱帮助分析：

```bash
npm run contract:local
```

显式的 `contract:local` / `contract:gitnexus` 才会执行 GitNexus 1.6.5 `analyze --force --index-only`，刷新 `.gitnexus/` 后检查同一变更契约；不重写 `AGENTS.md` / `CLAUDE.md`。本地默认 60 秒，`gitnexus` 命令默认 180 秒，可用 `GITNEXUS_ANALYZE_TIMEOUT_MS` 调整。

使用图谱时查看 `detect_changes`，再针对改动符号选择 `query`、`context` 或 `impact`。没有图谱工具或分析失败时，可以阅读调用者、检查数据兼容性并运行相关测试，诚实填写人工分析，不填写未经运行的图谱结论。

显式选择图谱命令后，下载或分析失败仍会让该命令报错；不会把失败当作分析成功，但也不影响独立的开发准备和功能测试。
